# ねこだるまおとし リリース後にやること

作成：2026-10-16
前提：Ver.1.0.0 は審査中。公開の方法は「手動でリリース」にしておく。
もとになった検討：`kazeellegard-dev/research` の `marketing/2026-10-16_free-marketing-proposal.md`

上から順に進める。☆ は、App Store の ID（`id` のあとの数字）が分かってからでないとできない作業。

---

## 0. 審査に通ったら（リリースの前）

- [ ] **リリースの方法を決める**
  - A. すぐリリースする
  - B. 予約注文を始める（リリース日を1〜2週間先にする。予約した人には、リリース日に自動でダウンロードされる）
  - B のほうが、リリース初日のダウンロードがまとまりやすい。予約の設定は App Store Connect の「価格および配信状況」
- [ ] **App Store の ID を控える**。App Store Connect の「App 情報」→「Apple ID」（数字）。アプリのページの URL は `https://apps.apple.com/app/id<数字>`
- [ ] **キャンペーンリンク用のプロバイダ ID を控える**。App Store Connect のアナリティクスにある、キャンペーンリンクを作る画面で出てくる URL の `pt=` の値。KAZE の全アプリで共通（画面の場所は App Store Connect で確かめる）
- [ ] **1.0.1 を申請する**（アプリ版のシェアのリンクを直した版。Web 版はもう直っている）
  1. `index.html` の `APP_SHARE_URL` を `https://apps.apple.com/app/id<数字>?pt=<プロバイダID>&ct=share` に変える ☆
  2. `package.json` の `version` を `1.0.1` にする
  3. Actions →「iOS アプリ」→ Run workflow（TestFlight にアップロード）
  4. TestFlight で、ゲームオーバー画面の「シェア」を押す。共有の画面が開き、App Store の URL と `#ねこだるまおとし` が入っているか確かめる
  5. 「このバージョンの新機能」は「シェアしたときのリンクを直しました」で申請する
  - 予約注文中に新しいビルドへ差し替えられるかは、まだ確かめていない。差し替えられなければ、リリースの後すぐに出す

## 1. リリース当日

### サポートサイト（`kazeellegard-dev/kaze-application`）☆

「近日公開」になっているところを「App Storeで入手」のリンクに変える（日本語・英語の両方）。

| ファイル | 変える場所 |
|---|---|
| `public/index.html`・`public/en/index.html` | アプリ一覧のねこだるまおとしの `app-card`（「App Store 近日公開」→ App Store へのリンク） |
| `public/apps/neko-daruma/index.html` | 29行目あたりと59行目あたりの `is-soon` のボタン 2か所。55行目あたりの更新履歴「近日公開予定です。」→「初回リリース」と日付 |
| `public/en/apps/neko-daruma/index.html` | 同じ 3か所（Coming soon） |
| `public/index.html`・`public/en/index.html` | お知らせ（`update-list`）に「ねこだるまおとし をリリースしました」を1件追加 |

- ほかのアプリの「App Storeで入手」ボタンと同じ書き方にする（`public/apps/knit2/index.html` を参考に）
- App Store へのリンクにも `?pt=<プロバイダID>&ct=site` をつけると、サイトから来た数が分かる

### Web 版（このリポジトリの `index.html`）☆

- [ ] タイトル画面かゲームオーバー画面に「App Store版」への小さな案内を1行出す（`ct=web` のリンク）
- [ ] Web 版はこれまでどおり全部遊べるままにする（Web 版は「遊んでシェアしてもらう入口」として使う）

### App Store Connect

- [ ] **プロモーションテキスト**（審査なしでいつでも変えられる）をリリース用にする。例：
  ```
  ねこがのった、お菓子のだるま落とし、配信開始！ タイミングよくたたいてPERFECTをねらおう。ミニゲームでもらえるチートねこ・チートハンマーで、きびしいステージも突破できるかも？
  ```

### X での告知

- [ ] 短い動画（10〜15秒、縦長、音あり）と App Store のリンク（`ct=x`）で告知する。動画のおすすめは「お菓子がぷるんっとつぶれる → ギリギリでねこが床にすわる」
- [ ] ハッシュタグ：`#ねこだるまおとし` `#猫` `#スマホゲーム` `#個人開発` `#インディーゲーム`
- [ ] 文面の例：
  ```
  iPhone・iPad向けのゲーム「ねこだるまおとし」をリリースしました🐱🍩
  ねこを落とさないように、お菓子の段をハンマーでたたき出すだるま落としです。無料で遊べます。
  #ねこだるまおとし #個人開発
  https://apps.apple.com/app/id<数字>?pt=<プロバイダID>&ct=x
  ```

## 2. リリースから1週間

- [ ] **ブラウザゲームの投稿サイトに Web 版を出す**：ふりーむ！、PLiCy（全年齢向けだけを扱うサイトなので、4+ のこのゲームに合う）。説明に App Store 版へのリンク（`ct=freem` など、サイトごとに分ける）
- [ ] **アプリ紹介サイトに申請する**：AppLiv などの掲載申請フォーム（1回だけ。手間が少ないものだけ）
- [ ] **配信者・VTuber に紹介する**：スマホゲーム・ブラウザゲームを遊んでいる、登録者数千〜数万人の人を 5〜10人選ぶ。その人の配信を見たうえで、短いメッセージを送る
  ```
  はじめまして、iPhone向けゲーム「ねこだるまおとし」を作っている KAZE Application です。
  ねこを落とさないようにお菓子の段をたたき出す、1回数分で遊べるだるま落としゲームです。
  ブラウザ版はインストール不要ですぐ遊べます：https://kazeellegard-dev.github.io/daruma_game/
  App Store版：https://apps.apple.com/app/id<数字>
  配信・動画化・収益化はご自由にどうぞ（連絡も不要です）。絵と音はすべて自作なので、権利の心配もありません。
  ```
- [ ] **X に週1〜2本、短い動画を投稿する**。ネタの例：のらねこの大群に崩される失敗、30段の山、ねこ10種類の紹介（1日1匹）、ひみつのハンマーのヒント

## 3. 次の更新（1.1.0 など）で入れるもの

- [ ] **評価の案内**：EL tools の `app/src/lib/review.ts` と同じ仕組み（3日以上遊んだ人に、Apple 標準の評価画面。バージョンごとに1回まで）。出すタイミングは「5ステージクリアのプレゼント箱の後」か「ハイスコア更新の後」。ゲームオーバーの直後は避ける
- [ ] **結果を画像でシェア**：結果画面のお菓子の山とねこを画像にして、シェアに添える。文字だけより押されやすい
- [ ] **アプリ内イベント**：更新ごとに App Store のイベントを出す（例：「新しいお菓子が登場」「ひみつのハンマーを探せ」）。最大10件作れて、同時に出せるのは5件
- [ ] 子ども（4+）も遊ぶので、「シェアするとアイテムがもらえる」のような仕組みは入れない

## 5. 効果の確かめ方（月に1回）

- App Store Connect の「アナリティクス」→「獲得」で、キャンペーン（`ct=`）ごとのダウンロード数を見る
  - `share`（アプリからのシェア）・`web`（Web 版）・`site`（サポートサイト）・`x`（X の告知）・`freem` など
- プロダクトページの表示数と、ダウンロードまでの割合（コンバージョン率）
- Web 版のアクセス数（GitHub Pages には標準のアクセス解析がないので、増やすなら別途検討）
- 効かなかった施策はやめ、効いたものに時間を回す

## 6. 英語圏について

ゲーム画面が日本語だけのうちは、Reddit などの英語圏への発信はしない。英語に対応したら、r/WebGames・r/playmygame・r/indiegames に Web 版を出すことを考える（「Daruma otoshi」は海外では珍しく見えるので、反応が得られる見込みはある）。
